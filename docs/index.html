A single agentic rollout

A tool-using agent is given a task.

At each step, the agent takes an action: a tool call or a message to the user.

The environment responds with an observation: a reply from the user or the output of a tool.

One rollout produces a long sequence of actions and observations…

…until the agent decides it has finished the task.

A grader then checks the final state to determine whether the agent succeeded. Here, it failed.

Could we recover the outcome without the grader?

Can the outcome be read from the actions and observations alone?

2

Where did it go wrong?

Somewhere in its rollout, the agent took an action or received an observation that led to its failure.

We can rewind to an earlier step and resample from there to see whether the outcome changes.

If completions resampled from the same prefix both succeed and fail, the agent is still stochastic at that point: its fate isn’t sealed.

Resampling from enough points would map out every path the agent could take on this task. But the number of rollouts this requires is far too large in practice.

What we can afford is a few dozen independent rollouts of each task from the same agent, which is exactly what GRPO samples during RL post-training.

Many steps are nearly identical across rollouts, even at different points: the same action, or the same question phrased differently.

By clustering similar steps across rollouts into shared states, every rollout becomes a path through a map of the agent’s behavior on the task.

Each rollout’s success or failure marks the states and connections it passes through, showing which parts of the map lead to success and which to failure.

We hypothesize that treating an agent’s rollouts on a task as a map of its behavior reveals which actions and observations predict how a rollout will end.

3

The finding

To test this, we hide the outcomes of a third of the rollouts.

A simple classifier, fit on the remaining rollouts, learns which states and transitions lean toward success or failure.

It then reads each hidden rollout’s path through the map and predicts how it will end.

When the outcomes are revealed, the rollouts that succeeded mostly rank above the ones that failed.

Across three benchmarks and three models, simple classifiers fit on each task’s own rollouts predict held-out outcomes at up to

0

AUROC: how often a held-out success is ranked above a held-out failure

Successes and failures separate: the outcome can be read from the actions and observations alone.

4

The obstacle

That classifier learned from the labeled rollouts of this one task:

0

labeled rollouts behind it

During RL training, a task supplies only one batch of rollouts at a time, and with fewer labels, per-task classifiers predict worse.

And none of it carries over. A new task has its own states, so its classifier starts again from zero.

So instead of fitting a classifier to each task, we learn the representation itself, across many tasks.

5

Precog-RM

Precog-RM learns that representation: one model, trained across many tasks and agents, that turns a rollout into a single point.

Each action and observation is embedded by a frozen text encoder, then projected into a smaller space.

A small transformer reads the steps together, so each one is seen in the context of the rest of the rollout.

Averaging its outputs gives one point for the whole rollout, or for any prefix of it:

0

dimensions

As the rollout unfolds, its point moves through this space and settles as steps arrive.

On a new task, one labeled batch of rollouts gives two prototypes: the average point of its successes and of its failures. A rollout is scored by which one it lies closer to, with nothing fitted.

Where text embeddings relate steps by what they say, Precog-RM relates whole rollouts by how they end.

6

The proof

A variant trained on prefixes scores a rollout while it runs: after each step, the rollout so far becomes a point that drifts toward the prototype it resembles.

It needs few labels. With two labeled rollouts per class, it matches what per-task classifiers reach with eight.

0

labeled rollouts per class

It carries to agents it never trained on, scoring their rollouts nearly as well as those of agents it did.

Mid-rollout, it calls an outcome only once it is confident, and holds off when the signal isn’t there.

So many rollouts can be called before they end. During RL training, that is compute that never needs to be spent.

7

The payoff

In GRPO training, an agent attempts each task in groups of rollouts. The first group on a task runs to the end, and its outcomes give the task’s two prototypes.

Every later rollout is scored after each step. Once its prediction is confident, the rollout stops and takes the predicted outcome as its reward.

Across training runs, this cuts the compute of training by up to

0

fewer training FLOPs, with the trained agent’s pass@1 within one standard deviation of standard GRPO

Rollouts whose outcome is already decided never need to be finished, and the way the agent learns stays the same.

8

Back to the beginning

We set out to learn a representation that captures the critical behavioral patterns of agents on long-horizon, tool-calling tasks.

Precog-RM keeps the outcome signal in a rollout’s actions and observations, and carries it to new tasks and agents from a single batch of labels.
